# 短剧演员订阅（ShortDramaActorSubscribe）

跟着喜欢的**短剧演员**追剧：合并 TMDB、豆瓣与**短剧百科**的演员作品列表，把作品铺成作品墙；
**你订阅哪部，插件才下哪部**。下载落盘后由**外部整理器**入库 —— 本插件默认不参与整理。

```
配置演员 → 轮询自动刷新作品墙 → 你订阅（单选 / 多选批量）→ 剧名搜索站点 → 名称/年份匹配
         → 择优一包 → 下载 → 账本去重 → 外部整理器入库
```

> **两条铁律（用户定稿 2026-10-14）**
> 1. **演员作品自行刷新** —— 定时轮询只刷新作品墙（并重试你订阅过、还没下到的），新作品自动出现。
> 2. **订阅的作品才下载** —— 未订阅的作品**永远不会**被提交下载。
>    「自动下载」开关默认关闭；一旦打开，轮询会把快照里所有没下过的作品挨个下回来
>    （演员到几十上百位就是上千个种子，且提交后不可逆），故默认关闭。

## 为什么不用宿主的订阅系统

短剧在 TMDB / 豆瓣上**大量没有条目**，宿主识别器建不起媒体身份，订阅永远不会触发。
实测：用剧名调宿主 `/search/title` 能命中 2 条资源，但两条的 `media_info` 全是 `null`
——订阅落库后搜索环节直接空转。

所以本插件**绕过身份识别**，走「**剧名 → 站点搜索**」直达资源：
- 「发现」用 TMDB + 豆瓣 + **短剧百科**的演员作品表（拿剧名与年份）；其中**短剧百科**
  经跨插件通道调用 `ShortDramaBaikeSource`（duanjubaike.org，短剧覆盖最全的一等来源，
  默认开启，可在配置页关闭）。百科作品卡不带年份，因此「年份缺失放行」是常态；
- 「匹配」用剧名 + 年份做**本地判断**（不依赖宿主识别）；
- 「去重」由插件自己的账本负责：下载成功立刻记一笔（含 `torrent_hash` / 站点 / 集数 /
  演员 / 来源），按「归一化剧名|年份」判重，不依赖宿主识别器；
- 「整理」**默认不做**：下载目录就是宿主「目录管理」里的那个目录，入库交给已经在监听它的
  外部整理器（如 `shortdramaorganizer`）。同一台机器上跑两个整理器会重复入库，
  所以本插件的自带整理器默认关闭，需要时可在配置页打开。

宿主订阅链在这里只做**可选**的一件事：本插件不写宿主订阅表，因此不受宿主订阅
去重 / 季集识别的约束，长尾短剧也能追。

## 功能

| 能力 | 说明 |
| --- | --- |
| 演员配置 | 支持**演员名称**（自动搜索并缓存 ID）、**豆瓣人物主页链接 / 人物 ID**（推荐，最稳，不消耗搜索配额）、**TMDB 人物 ID**；多位演员用逗号 / 换行 / 顿号 / 分号分隔 |
| 双源发现 | 每位演员同时拉 **TMDB 演职员表**、**豆瓣影视作品集**与**短剧百科演员页**（经跨插件调用 `ShortDramaBaikeSource`，默认开启、可关），按「归一化剧名 + 年份」合并去重（一侧缺年份时按剧名归并），先到者补齐别名 / 海报 / 评分 |
| 短剧页作品墙 | 侧栏「短剧」入口（与宿主「电影订阅 / 电视剧订阅」同组）把**演员的全部作品**铺成**海报卡片墙**（与「豆瓣演员订阅」的作品墙同一套视觉）：海报 + 状态徽标（订阅中 / 待订阅 / 冷却中 / 已下载 / 已整理）+ 来源徽标（豆瓣 / TMDB / 短剧百科）+ 类型 / 年份 / 评分 / 出演演员；顶部工具条支持关键字搜索、状态按钮组、演员 chip 筛选与**多选**，每页 20 张、可翻页 |
| 订阅即下载 | 每张卡片一个**订阅按钮**：立即对该剧走一遍「搜索 → 匹配 → 择优 → 下载」。**订阅是持久的** —— 这次没下到（站点暂无资源 / 下载器提交失败）不算失败，作品留在**订阅表**里，之后每轮自动重试，直到下到为止；已在账本里则按钮变为「已下载 / 已入库」，订阅中的显示「订阅中」并可随时取消 |
| 多选批量订阅 | 工具条「多选」按钮进入多选模式：点卡片即勾选（已下载 / 已入库的不可选），支持「选中本页可订阅的」，一次批量订阅 / 批量取消订阅；后端只把选中的写进订阅表并登记后台任务依次下载（同步接口会超时），进度看状态徽标 |
| 刷新作品 | 作品墙的「刷新作品」只重解析演员作品快照，**绝不触发下载**（想「先看看有什么」时用这个） |
| 剧名匹配 | 剧名**含序号精确匹配**（「闪婚老公是豪门 第二季」不会命中第一季）；年份缺失**放行**，两边都有年份时容忍 ±1 年误差 |
| 择优 | 同一部剧多个资源包时按 **做种数 → 体积 → 分辨率** 顺序择优，只下一包；**多剧合集包**直接排除 |
| 去重 | 账本键 `归一化剧名\|年份`（**不含集数**）——集数只作信息展示，因为短剧常做整包整合，集数不同不代表不是同一部 |
| 冷却 | 未命中（站点搜不到 / 下载提交失败）记 **24 小时冷却**，避免每轮对几十部剧空搜；成功下载即从冷却表移除（账本接手去重） |
| 整理入库（可选，默认关闭） | 打开后启用独立定时任务：按账本定位下载完成的文件 → 硬链接 / 软链接 / 复制 / 移动到媒体库目录 → 写最小 NFO（不依赖宿主识别器）。**默认不参与整理**，因为入库通常已由外部整理器负责；关闭时既不注册定时任务，页面也不显示「立即整理」入口 |
| 下载器 / 目录 | 配置页的**下载目录与下载器直接读宿主的「目录管理」与「下载器」配置**，并自动勾出系统默认项与「短剧」目录，不用手抄路径 |
| 通知 | 通过宿主通知渠道推送本轮结果（新下载清单 + 异常摘要） |
| 远程命令 | `/shortdrama`：在宿主聊天里直接触发一轮订阅轮询 |

## 配置项

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | 启用插件。**必须保存一次配置**才会出现侧栏入口与定时服务 |
| `sidebar_nav` | bool | `true` | 是否在侧栏显示「短剧」入口（关闭后插件照常运行） |
| `actors` | str | 空 | 演员列表（后端以换行串存储，配置页以逗号分隔编辑）。推荐粘贴豆瓣人物主页链接或人物 ID |
| `sites` | list | `[]` | **搜索站点**（站点 ID 列表），短剧专站 / 带短剧分类的站优先 |
| `prefer_short_drama_category` | bool | `true` | 优先在站点的「短剧」分类里搜索（命中率更高，也省请求） |
| `downloader` | str | 空 | 下载器名，取自宿主已配置下载客户端（与系统「下载器」配置同源） |
| `download_path` | str | 空 | 下载目录，取自宿主「目录管理」的下载目录 |
| `library_path` | str | 空 | 媒体库目录（仅自带整理器需要），与下载目录**成对**读取 |
| `transfer_type` | str | `link` | 搬运方式，仅自带整理器需要。与宿主「整理方式」同一套取值：`link` 硬链接（推荐，需同盘）/ `softlink` 软链接（**跨盘可用**，媒体库侧是真实目录、文件为符号链接，不占空间）/ `copy` 复制 / `move` 移动 |
| `interval_hours` | int | `6` | **作品发现周期（小时）**：每轮刷新演员作品墙，并重试「已订阅但还没下到」的作品。发现层（演员作品快照）只在到期时才真的请求豆瓣 / TMDB，见 `snapshot_hours` |
| `snapshot_hours` | int | `24` | **作品快照的整体刷新间隔（小时）**。期间轮询直接用缓存 —— 豆瓣匿名额度极紧，每轮都重解析纯属浪费且必撞限流 |
| `retry_minutes` | int | `20` | **解析失败后的重试间隔（分钟）**。登录态失效 / 限流这类失败是可自愈的，20 分钟后再单独重试一次，不必等满一天 |
| `auto_download` | bool | **`false`** | **订阅制开关**。默认关闭 = 轮询只发现，只有你（单选 / 多选）订阅的作品才会下载。打开后轮询会把快照里**所有没下过的作品**挨个搜索下载（等于按演员全量追剧）—— 演员多时会把下载器灌爆且不可逆，慎开 |
| `use_baike` | bool | **`true`** | **短剧百科发现源**。经跨插件通道调用 `ShortDramaBaikeSource` 按演员名取 duanjubaike.org 的全部参演作品。每位演员**首次**解析多花约 10 秒（站外索引检索一次），之后按缓存的百科 ID 直连演员页；关闭即回到「TMDB + 豆瓣」并集 |
| `organize_enabled` | bool | **`false`** | 是否由**本插件**整理入库。默认关闭 —— 入库一般由外部整理器负责，两个整理器同时跑会重复入库 |
| `organize_interval_minutes` | int | `30` | 自带整理器的扫描周期（分钟），仅 `organize_enabled` 打开时生效 |
| `notify` | bool | `true` | 完成后发送通知 |
| `douban_cookie` | str | 空 | 手工粘贴的豆瓣 Cookie（留空则自动复用宿主 CookieCloud 登录态） |
| `proxy` | bool | `false` | 走宿主配置的代理访问豆瓣 / TMDB |
| `max_works` | int | `10` | 每位演员保留的作品条数（1–10）。上限 10 是豆瓣接口限制，不是插件限制 |
| `onlyonce` | bool | `false` | 保存配置后立即执行一轮（勾选后自动复位） |

## HTTP 接口

挂载在 `/api/v1/plugin/ShortDramaActorSubscribe/<path>`，全部 `bear` 鉴权。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/config` | 获取运行时配置 + 下拉候选（含 `douban_cookie_source`） |
| PUT | `/config` | 合并更新配置，持久化后重新初始化插件 |
| GET | `/options` | 站点 / 下载器 / 整理方式候选 + **系统目录** + 推荐初值 |
| GET | `/status` | 运行概览、账本与冷却列表 |
| GET | `/works` | **演员作品墙**：摊平快照的每条作品 + 其状态 + 汇总 |
| POST | `/works/subscribe` | 订阅一部作品：立即搜一次，没下到就留在订阅表持续重试（body：`key` / `title` / `year`） |
| POST | `/works/unsubscribe` | 取消订阅（body：`key`） |
| POST | `/works/subscribe_batch` | **批量订阅**（body：`keys: [...]`）：写入订阅表并登记后台任务依次下载 |
| POST | `/works/unsubscribe_batch` | 批量取消订阅（body：`keys: [...]`） |
| POST | `/works/refresh` | 只刷新演员作品快照，不下载 |
| POST | `/run` | 立即执行一轮：刷新作品 + 重试订阅（订阅制下**不会**下载未订阅的作品） |
| POST | `/organize` | 立即整理一次（`organize_enabled=false` 时直接返回关闭原因，不做任何动作） |
| POST | `/unmatch` | 从账本移除一条记录（允许重新下载） |
| POST | `/miss/clear` | 清空未命中冷却 |
| GET | `/search_actor?name=` | 按名称搜索 TMDB / 豆瓣演员 |
| POST | `/clear` | 清空账本 |

> 插件动态路由**不套宿主的 `Response[T]` 外壳**，因此插件接口一律自行返回 `{success, data}`。
>
> 宿主用 `router.add_api_route(**api)` 注册路由，参数由 **FastAPI 注入**：
> `Optional[Dict[str, Any]] = None` 会被识别成 **requestBody**，`name: str = ""` 则是 **query**。

### `/works` 的数据形状

```jsonc
{
  "items": [
    {
      "key": "盛夏芬德拉|2025",        // 与账本同源的身份键
      "title": "盛夏芬德拉", "year": "2025", "type": "电视剧",
      "alt_title": "",
      "actor": "王格格", "source": "douban", "media_id": "37527115",
      "poster": "https://img2.doubanio.com/view/photo/…/p2926420251.webp",
      "vote": 7.6,                    // 0 表示无评分（卡片上不显示）
      "state": "pending",              // pending / cooling / downloaded / organized
      "remaining_minutes": 0,          // 冷却中时有意义
      "site_name": "", "torrent_title": "", "time": ""   // 已下载时有意义
    }
  ],
  "summary": {"total": 11, "pending": 10, "cooling": 1, "downloaded": 0},
  "refreshed_at": "2026-10-13 21:47:00",
  "running": false, "configured": true,
  "actors": [{ "key": "王格格", "name": "王格格", "douban_id": "…", "tmdb_id": "…" }]
}
```

状态由**账本 + 订阅表 + 冷却表**推导（不额外存一份状态），排序固定为
`subscribed → pending → cooling → downloaded → organized`，所以「要处理的」永远排在最前面。

| 状态 | 含义 |
| --- | --- |
| `subscribed` | **你订阅了、还没下到**（每轮自动重试，直到下到为止）；卡片按钮是「取消订阅」 |
| `pending` | 既没订阅也没下载；卡片按钮是「订阅」（订阅制下**不会**自动下载） |
| `cooling` | 搜过但站点暂无资源；`remaining_minutes` 给剩余冷却分钟 |
| `downloaded` / `organized` | 账本命中，按钮不可点 |

`poster` / `vote` 是卡片墙要用的展示字段：豆瓣取 `subject.cover.large.url` 与
`extra.rating_group.rating.value`，TMDB 由 `poster_path` 拼 w300 地址、取 `vote_average`。
**升级前存下的快照没有这两个字段**，此时 `/works` 返回空串与 0（卡片显示占位图），
刷新一次作品即补齐。

## 其他扩展点

- **定时服务**：`get_service()` 注册两个发现层服务（+ 可选整理）：

  | 服务 | 默认节奏 | 做什么 |
  | --- | --- | --- |
  | `<类名>.Refresh`（作品发现） | `interval_hours`（6 小时） | 刷新演员作品墙（快照到期才真去请求，否则用缓存）+ **重试订阅表**；订阅制下不下载未订阅的作品（打开 `auto_download` 才会全量下载） |
  | `<类名>.Retry`（解析失败重试） | `retry_minutes`（20 分钟） | 只重解析上一轮失败的演员，**不搜索、不下载**；没有到期对象时完全静默 |
  | `<类名>.Organize`（整理扫描） | `organize_interval_minutes`（30 分钟） | 仅 `organize_enabled=true` 且下载目录与媒体库目录都配好时注册 |

  **为什么把发现层拆成两条节奏**（用户 2026-10-14 定稿）：快照整体**一天刷一次**就够
  （新作品最多晚一天被发现，而站点的未命中冷却本来就是 24 小时），但登录态失效 / 限流这类
  失败是可自愈的，等满一天体验太差。所以失败记录走 20 分钟的独立重试任务
  （判定见 `is_retry_candidate()`：`state=="waiting"`、或老快照里没作品、或新加的演员）。
  两条节奏不重叠：整表按 TTL 到期的那次刷新只由轮询任务做。

  整理默认关闭（入库交给外部整理器），所以默认只有两个服务；未启用 / 未配置演员与站点时
  连订阅轮询也不注册（重试服务只要求配置了演员 —— 发现层不需要站点）。

  ⚠️ **改配置不会重新注册服务** —— 宿主的服务 reconcile 只在插件重新加载时跑。
  在配置页改完 `organize_enabled` 并保存后，插件实例立即按新配置行事（`organize_once` 会
  直接短路），但调度器里那条旧任务要等下一次插件重载才消失。想立刻生效就重载一次插件。

  ⚠️ 传给被调函数的参数必须写在 **`func_kwargs`** 里，**不能写成 `kwargs`**。宿主注册服务时会把
  `service["kwargs"]` 原样展开给 `scheduler.add_job()`（见宿主 `scheduler/reconcile.py` 的
  `update_plugin_job`），而 `trigger` 正是 `add_job` 自己的形参名 —— 写成 `kwargs` 会让
  `add_job()` 收到两个 trigger 并抛 `got multiple values for argument 'trigger'`，
  **注册被静默拒绝、定时任务永远不会执行**（宿主只写一条 ERROR 日志）。
  排障：`docker logs moviepilot | grep 注册插件`（成功 INFO / 失败 ERROR）。
- **一次性任务**：`POST /run` 与 `POST /works/refresh` 只登记一次性任务
  （`add_plugin_once_job(..., func_kwargs={"trigger": ...})`）并立即返回，避免长任务触发 HTTP 超时；
  两个动作各自用独立 `job_id`（`refresh_once` / `refresh_works_once`），避免互相覆盖。
- **侧栏入口**：`nav_key=main`（`./AppPage`），`section=subscribe`、`permission=subscribe`、
  图标 `mdi-movie-open-star-outline`，与宿主「电影订阅 / 电视剧订阅」并列落在「订阅」组。
  受 `enabled` 与 `sidebar_nav` 双重控制。
- **仪表板**：`key=overview`，`cols/sm/md = 12/6/4`，刷新间隔 300s。
- **远程命令**：`/shortdrama` → `EventType.PluginAction` → `on_plugin_action`
  （`data.action = "shortdramaactorsubscribe_refresh"`，只处理属于本插件的 action）。

## 前端（Vue 模块联邦）

`get_render_mode()` 返回 `("vue", "dist/assets")`，宿主直接加载 `dist/assets/remoteEntry.js`。

```
src/
├── api.ts              # 接口封装 + 宿主深链构造（媒体详情页 / 资源搜索页）
├── types.ts            # 与后端 payload 对齐的 TS 类型
├── WorkGrid.vue        # 作品海报卡片墙（内部复用组件，不作为联邦暴露入口）

├── Dashboard.vue       # 仪表板小组件
├── AppPage.vue         # 侧栏全页（nav_key=main），复用 Page
└── AppPageSettings.vue # 运行状态页
```

### 面板上的「设置」入口

宿主的侧栏全页壳（`app-D_4dm5xE.js`）只给插件组件注入 `api` / `nav-key` /
`plugin-id` / `source-plugin-id` / `native-subscribe` 几个 props，**不提供任何设置入口** ——
必须由插件自己在面板上给出，否则用户只能绕「设置 → 插件 → 找到本插件 → 配置」。

`Page.vue` 标题栏因此带一个「设置」按钮（`mdi-cog-outline`）：

- 点击时**先把最新配置取回来**再挂载 `Config.vue`。该组件只在 `onMounted` 里读一次
  `initialConfig`，先开弹窗（快照为空）再回填会让表单全空，用户一保存就把已有配置清掉。
- 弹窗内复用联邦暴露的**同一份** `./Config` 组件（构建产物确认是同一个 chunk，没有重复打包），
  因此面板内改配置与插件详情页的配置弹窗是同一套字段、同一套校验，不存在两套配置口径。
- 保存由 `Config.vue` 自己 `PUT /config` 落盘（宿主插件管理页那条 `save` 事件链在全页场景
  拿不到），保存后面板立即重拉配置、状态与作品墙，并按新配置决定是否显示「立即整理」。

### 作品墙与订阅按钮

卡片墙的渲染全部收在 `WorkGrid.vue`（与「豆瓣演员订阅」的同名组件对应），
`Page.vue` 只负责取数、筛选与把动作转给后端。每张卡片：

```
海报（经宿主图片代理取图）
  ├─ 左徽标：状态（订阅中 / 待订阅 / 冷却 / 已下载 / 已整理）
  └─ 右徽标：来源（豆瓣 / TMDB）
标题（两行截断） / 类型 chip · 年份 · 评分 / 出演演员 / 种子原名（已下载时）
[ 订阅 / 取消订阅 ]（状态相关） [详情↗] [搜索资源↗]      ← 多选模式下改为左下角勾选框
```

- 数据来自 `GET /works`。前端**不缓存状态**，每次操作后重拉，因此「订阅」成功 /
  进订阅表 / 已下载都能立刻反映到卡片徽标、按钮与顶部汇总。
- 「订阅」按钮走 `POST /works/subscribe`（**不是**前端直接调站点搜索）：后端在
  `self._lock.acquire(blocking=False)` 保护下复用整轮任务的 `_process_candidate`
  —— 搜索、匹配、择优、下载**完全同一条链路**，所以单项订阅、批量订阅与轮询重试的判定
  口径一致，不会出现「手动能下、自动下不了」这类偏差。
- **订阅是持久的**：这次没下到（站点暂无资源 / 下载器提交失败）**不算失败** ——
  作品进订阅表，卡片显示「订阅中」，之后每轮自动重试直到成功（成功后进账本、移出订阅表）。
  卡片按钮变成「取消订阅」，随时可以反悔。
- **多选批量订阅**：工具条「多选」进入多选模式 —— 点卡片即勾选（已下载 / 已入库不可选）、
  「选中本页可订阅的」一键勾选当页、操作条分别给出「批量订阅（N）」与「批量取消订阅（N）」。
  批量提交走 `POST /works/subscribe_batch`：只写订阅表 + 登记**后台任务**依次下载
  （一次选几十部时同步接口会超时），进度看状态徽标。
- 已下载 / 已整理的剧按钮置灰（「已下载 / 已入库」），从交互上杜绝重复下载；
  想重新下载请到下方账本里「移出账本」。
- 已下载 / 已整理的剧按钮置灰（「已下载 / 已入库」），从交互上杜绝重复下载；
  想重新下载请到下方账本里「移出账本」。
- 「详情」跳宿主自带的媒体详情页（与探索页点进媒体同一个页面），
  宿主详情页强依赖中文媒体类型，拿不到类型的作品不显示这个入口。
- 「搜索资源」跳宿主自带的资源搜索页，带上插件配置的搜索站点，用于人工复核。
- 未配置搜索站点 / 下载器 / 下载目录时，按钮会直接给出可读原因（`configured: false`），
  而不是静默失败。

### 为什么默认不自动下载（2026-10-14 事故复盘）

**经过**：当日 14:14 定时轮询触发，到 16:28 之间向下载器提交了 **114 个种子**，
用户完全没有订阅过这些剧。

**两条根因**：

1. **没有下载闸门**：`execute_task` 会把快照里**所有不在账本中**的作品挨个搜索下载，
   作品墙的「新」标记只是展示，与下载无关。演员名单到 100 位 × 每位最多 10 部 =
   快照 1250 部 ⇒ 只要账本空就会一路下到底（本轮速度推算约需 28 小时）。
2. **账本只在整轮结束时落盘**：`_save_ledger` 原本只在 `execute_task` 循环之后调用一次。
   候选一多，轮次必然跑不完（本次 16:36 宿主 reconcile 重载插件把它打断）⇒
   本轮 114 部**全部丢失去重记录**，下一轮会再下一遍，形成死循环。

**现在的做法**：

- 轮询只做发现 + 重试订阅表（`auto_download` 默认 `false`）；
- 下载权交给用户：单选「订阅」或**多选批量订阅**，订阅持久化、每轮自动重试；
- 账本**每成功一部立刻落盘**（`_save_ledger` 在成功分支里调用），中断不再丢记录。

### 解析失败：等待重试，不逐条报错

演员作品解析失败绝大多数是**临时的**：豆瓣登录态过期、接口限流、网络抖动。这类失败由
独立的失败重试任务在 `retry_minutes`（默认 20 分钟）后**自动重试**，所以面板
**不再逐条铺错误**，改为后端先归一成状态、前端只给一句汇总：

| 后端 `actors[].state` | 含义 | 面板表现 |
| --- | --- | --- |
| 空串 | 正常取到作品 | 只显示作品数（TMDB 单边失败不影响） |
| `waiting` | 临时性失败（登录态 / 限流 / 未知异常） | 工具条下方一句「等待自动重试」，原因在该演员的筛选 chip 悬停里 |
| `empty` | 豆瓣确实没有影视作品集、短剧百科未收录该演员、或 TMDB 未配置 | 一句中性说明，不当作故障 |

> 面板**不单列演员清单**：演员名只在作品墙的筛选 chip 行出现（外加「全部演员」），
> 避免同一批名字在页面上出现两遍。每位演员的作品数画在 chip 上，豆瓣 / TMDB ID、
> 作品数与失败原因收进 chip 的悬停提示。

配套实现（`__init__.py`）：

- `classify_error()` 把失败文案归一成原因码（`douban_auth` / `douban_rate` / `douban_empty` /
  `tmdb` / `other`），`record_state()` 再据此给出展示状态 —— 前端不复制一套关键词判定。
- **同一轮内短路**：第一位演员确认登录态失效后置 `self._douban_blocked`，本轮剩余演员
  不再逐个去撞豆瓣（省配额、少刷屏），直接复用同一原因，等下一轮再试。
- **失败只影响自己**：重试任务只挑 `is_retry_candidate()` 认定的失败记录，其余演员的
  快照原样沿用（不写盘、不打日志、不碰网络）—— 一位演员失败不会让全表重刷一遍。
- 日志从「每位演员一条 warning」改为**整轮汇总一条 info**
  （`… 3 位演员本轮未取到作品（豆瓣 Cookie 已失效…），等待下一轮自动重试：甲、乙、丙`），
  重试成功后再补一条（`解析失败重试完成：重试 3 位演员（…），候选 N 部，已恢复 2 位：甲、乙`）。
- 完整原因仍保留在 `GET /status` 的 `actors[].errors` 中，悬停该演员的筛选 chip 即可看到，排查不受影响。

> 豆瓣登录态失效是其中**唯一需要用户动作**的失败：重新登录豆瓣并把 Cookie 同步到
> CookieCloud 即可，插件下一轮自动恢复（不需要重启插件或重新保存配置）。

### 下载路径与下载器：读系统配置，不手抄

配置页的下载目录 / 下载器不再是纯手填输入框：

| 数据 | 来源 |
| --- | --- |
| 目录列表 | `DirectoryHelper().get_dirs()`（宿主「目录管理」，**下载目录与媒体库目录成对**），按 `priority` 排序 |
| 「短剧」目录 | 目录的 `name` / `media_category` / `download_path` 任一含「短剧」即标记 `is_short_drama` |
| 推荐初值 | `defaults`：优先命中「短剧」目录（没有就取第一个），连同它的 `library_path` 一起下发 |
| 下载器列表 | `DownloaderHelper().get_configs()`，并标出系统里 `default=true` 的那个 |
| 系统默认下载器 | `get_configured_system_config()[SystemConfigKey.Downloaders]` 里 `default=true and enabled` 的条目 |

于是 `/options` 返回：

```jsonc
{
  "sites": [...], "downloaders": [{"title": "qb", "value": "qb", "default": true}],
  "transfer_types": [...],
  "directories": [{"title": "短剧（/vol00/…/短剧/）", "value": "/vol00/…/短剧/",
                   "library_path": "/vol2/1000/media/短剧/", "is_short_drama": true}],
  "defaults": {"downloader": "qb", "directory": "/vol00/…/短剧/",
               "library_path": "/vol2/1000/media/短剧/", "directory_name": "短剧"}
}
```

配置页在**字段为空时**用 `defaults` 预填，并提供「采用系统推荐」按钮一键套用；
选中某个目录时**联动填好媒体库目录**（两者在宿主里本来就是一对），避免只改一半。
已有值的字段不会被覆盖。

> ⚠️ 一个踩过的坑：宿主 `ServiceBaseHelper.get_configs()` 返回的是 **`{name: conf}` 字典**
> （不是列表），且 `conf` 是 pydantic 对象而非 dict。早期按列表写 `for item in get_configs()`
> 迭代到的是字符串键，`item.get(...)` 抛 `AttributeError` 被 `except` 吞掉 —— 表现是
> **下载器下拉永远是空的**，且日志里一句提示都没有。现在键与字段两种来源都取，
> 并用 `_conf_field()` 兼容对象 / dict 两种形状。

### 站点域名要归一化（否则表现为「站点不存在」）

宿主 `SitesHelper().get_indexers()` 每条记录里的 `domain` 字段是**完整 URL**
（`https://www.ptskit.org/`），而 `SitesHelper().get_indexer(domain)` 的匹配键是**纯域名**
（`ptskit.org`，与 `GET /api/v1/site/supporting` 的字典键一致）。把 URL 原样喂进去一律返回
`None`，外在表现就是日志里的「站点 … 不存在！」—— 而且**每个站点都搜不到东西**。

插件统一走 `site_domain_of()` 归一化（去协议 / 端口 / `www.`），再用
`site_domain_candidates()` 展开成候选逐个实探（含「子域退一级主域」，因为下载链接常落在
`pt.xxx.com` 这类子域上）。命中哪个后续就一直用哪个，保证 `browse(domain=…)`、
分类探测与 Cookie 回查拿到的是同一个键。

### 深链

作品行可跳宿主自带的**媒体详情页**与**资源搜索页**：`<应用基址>#/media?…` /
`<应用基址>#/resource?…`。两个易错点：① 宿主前端是 **hash 路由**，直接拼 `/resource?…`
会落到 SPA 首页（看起来像「点了没反应」）；② 资源搜索页的媒体源清单只在探索 / 媒体详情
等路由预加载，**`/resource` 不在其中**，所以深链必须**同时带 `media_id` 与 `keyword`**
才能保证「打开就搜」（有身份走精确搜索、否则退回按剧名模糊搜索）。应用基址取
`location.href.split('#')[0]`，反代到子路径也不会拼错。

构建：

```bash
npm install --ignore-scripts   # 沙箱内需跳过 postinstall
node node_modules/vite/bin/vite.js build
```

产物写入 `dist/`。**联邦产物必须随插件提交**（仓库根 `.gitignore` 忽略 `dist/`，
提交时用 `git add -f`），因为运行时不重新构建，宿主直接读取该目录。

## 匹配与择优规则

| 环节 | 规则 |
| --- | --- |
| 剧名匹配 | 归一化（去空格 / 全半角 / 标点）后**要求包含剧名**；剧名自带序号（第 N 季 / 第 N 部 / 罗马数字）时**序号也必须一致** |
| 别名 | 豆瓣 `alt_title` 与 TMDB 译名都参与匹配，任一命中即可 |
| 年份 | 资源标题 / 描述里能提取到年份时与作品年份比对，容忍 **±1 年**；**作品年份缺失一律放行** |
| 排除 | 标题出现「合集 / 全集打包 / 多剧」等特征的**多剧合集包**直接排除 |
| 择优 | 依次比 **做种数（多者优先）→ 体积（大者优先）→ 分辨率（高者优先）**，只取第一包 |
| 记账 | 下载成功立刻写账本（含 `torrent_hash` / 站点 / 集数 / 演员 / 来源），整理完成再补 `organized` 标记 |

## 豆瓣 Frodo 接口适配要点

实测（2026-10）移动端接口的几个易错点，都足以让整条豆瓣链路**静默失效**（不报错、只是没数据）：

| 事项 | 结论 |
| --- | --- |
| 签名 | `_ts` 是**日期串 `YYYYMMDD`**（不是 Unix 时间戳），签名对象是**路径**（含 `/api/v2` 前缀，`quote(path, safe="")`），参数还需带 `os_rom=android`。任一项错 → 稳定 `400 签名错误` |
| 人物详情 | `/elessar/subject/{person_id}` 的真实结构是 `modules[type=work_collections].payload.collections[]` —— **比早期结构多一层 `payload`**（`module["collections"]` 恒为 `None`） |
| 作品集 ID | 集合自身的 `id` 是**空串**，可用的 ID 在 `payload.id`；作品**直接内嵌**在集合的 `works` 里（10 条） |
| 分页 | `/elessar/work_collections/{id}/works` 单次最多 10 条，且 `start > 0` 恒返回 `{"total": 0, "works": []}` —— **不支持翻页**，每位演员只能取最近 10 部 |
| 媒体类型 | 条目里 `subject.type` 恒为 `"subject"`，真实类型在 `subject.subtype`（`movie` / `tv`） |
| 年份 | 顶层无 `year`，位置是 `subject.extra.year` |
| 简介 | `subject.extra.short_info`，形如 `2026 / 中国大陆 / 短剧 / …` |
| 搜索限流 | `/search/subjects?type=person` 匿名约 **5 次**后 `403 {"msg":"need_login","code":103}`，**恢复窗口约 3 分钟**；带登录态（宿主 CookieCloud）单轮可解析约 **12 位**演员 |

> 排障提示：豆瓣侧任何失败都会写进该演员快照的 `errors`
> （例如 `豆瓣：人物详情里没有「影视」作品集（modules=[...]）`），
> `/works` 与配置页都能看到。**不要让失败路径静默 `return []`** —— 上面那条
> 「多一层 payload」的问题就是靠它一眼定位的（修复后同一位演员的作品数 1 → 11）。

## 兼容性

- 目标宿主：MoviePilot **V3**（`>=3.0.0`），已在 **v3.1.3** 实测。
- 仅从稳定入口导入：`app.sdk.*`（`plugin` / `logging` / `config` / `network` / `services` / `scheduler`）、
  `app.schemas.types`；不使用 `app.helper.*`、`app.utils.*`、`app.core.*`。
- 前端只用 Vuetify 组件。宿主初始化时把**整份组件表**都传给了 `createVuetify`
  （宿主入口产物里的 `createVuetify({ components: { ...iP, ...VI, VDialog: … } })`，
  `iP` / `VI` 合起来就是 `vuetify/components` 的全部导出），因此在 v3.1.3 上
  联邦组件调用任意 Vuetify 组件都能解析。但为稳妥起见，新增组件后仍建议
  `grep -o '_resolveComponent[^"]*("[^"]*")' dist/assets/*.js` 列出实际用到的组件名，
  与本插件已用过的集合比对一次（历史上曾有个别组件解析不到、静默渲染成空元素）。
