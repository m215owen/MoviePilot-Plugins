# 短剧演员（ShortDramaActorSubscribe）

跟着喜欢的**短剧演员**追剧：把演员名填进来，插件从**短剧百科**（www.duanjubaike.net）取回他们的
全部作品，铺成一面和宿主「探索」页同形的海报墙；看中哪部点「订阅」，走的就是
**MoviePilot 自己的订阅系统** —— 搜索、下载、整理全部由系统接管。

```
填演员 → 短剧百科取作品 → 作品墙（侧栏「短剧演员」）
                              ↓ 点「订阅」
                       宿主原生订阅对话框 → 系统订阅 → 系统搜索/下载/整理
                       （配置页指定了「订阅下载器」时改为直接提交，并带上下载器偏好）
```

> **一句话定位（2026-10-15 重写）**：本插件**只做发现**。
> 自建的站点搜索 / 择优下载 / 账本去重 / 自建订阅表 / 自建整理入库 / 自写 NFO
> 这一整条链路已**全部删除** —— 短剧百科已作为一等媒体数据源接入宿主框架（能出卡片、
> 能开媒体详情页），宿主的订阅系统认 `media_source` + `media_id` 这种显式身份，
> 因此订阅这件事交还给系统既更短也更可靠。

## 界面（侧栏「短剧演员」）

- 落在宿主侧栏的**订阅分组**里，与「电影订阅 / 电视剧订阅」并列。
- 版面自上而下固定为五块：**标题行 → 搜索行 → 视图标签条 → 视图槽位 → 卡片区**
  （卡片区与筛选区各自固定，切视图只换内容，版面不重排）。
- **搜索行**常驻在视图标签条**上方**，两个标签页共用同一条搜索：
  演员与作品**都查**（短剧百科同一站，两条检索链路并行，防抖 0.4 秒）；有词时搜索结果
  独占卡片区（先演员后作品两块），清空后回到当前标签页那一页。
- **视图标签条**（自绘标签，不是筛选 chip）：左起「**作品**」、「**已关注演员 N**」、「**发现演员**」。
  - 版式**照宿主探索页顶栏那排来源标签（TheMovieDb / 豆瓣 / Bangumi…）一比一复刻**：
    pill 圆角 20px + `0.9rem`/600 字重 + 底部 **3px 主色指示条**（宽 70%，选中时 `scaleX(0→1)`
    展开）+ 未选中 hover 的 **5% 主色底** + 标签溢出时的**右侧渐隐指示**与左右 **28px
    圆形滚动钮**（一次滑 200px，触摸端隐藏交给手势）。宿主那份是
    `src/layouts/default/components/HeaderTab.vue`（探索页的 VWindow 只是内容区，标签本身由
    `useDynamicHeaderTab` 注册到顶栏）—— 它是 scoped 的，联邦元素匹配不上 ⇒ 数值照搬、
    类名全自有前缀；颜色变量宿主用 `on-background`，这里换 `on-surface`（标签条画在面板
    surface 底上）。它**没有**整条下边框（选中态自带指示条），所以这条也一并去掉；
  - 演员卡与作品分类是两种东西，**不混在同一排里筛** —— 视图切换从筛选栏里彻底拿出来；
  - 标签状态记在本标签页里（进详情页返回后还在原来那一页）。
- **视图槽位**（标签条下面那一块，两页各装各的）：
  - **作品**标签页 → 作品维度筛选行（版权方 / 类型 / 年份 / 排序 / 媒体库）；
  - **已关注演员**标签页 → 演员页自己的两行（「分类」行 + 「已关注 · N 位演员」工具栏）；
  - **发现演员**标签页 → 「目录」行（演员 / 导演 / 编剧三颗 chip）+ 一行「已加载 N 位 / 加载更多」；
    数据源还没提供人物目录时，这一行直接显示它的说明（空态里也有同一句），不当成请求失败；
  - **槽位高度随内容自适应**（**不留白**）：演员页只有两行，槽位就只有两行高，
    卡片区紧跟着往上收（代价是切标签时卡片区会有一段位移）。
- **演员页的卡片**与搜索结果里的演员卡**同一个组件**（`src/ActorCard.vue`）—— 头像
  （2:3 海报位）+ 悬停浮层（身份行 / 姓名 / 简介 + 左「百科页」右「取消订阅」按钮排）完全一致。
  - 演员页槽位里有一行**「分类」**，与作品页「类型」行**同一套 chip 用法**
    （左 `VLabel` + 一排 `VChip{filter, tile}`，带计数角标，再点一次取消 = 全部）：
    **女演员 N / 男演员 N / 未标注 N**。选中某一类就只铺那一类，不选则全部。
    站点性别字段英文 `Female` / `Male` 与中文都能认，认不出的进「未标注」而不是丢掉。
    真机当前 54 / 22 / 20。分类选择记在本标签页里。
    **正开着某个整页视图时点分类**（或点刷新按钮），会先退出整页视图、回到演员卡片墙 ——
    否则主体还是那份作品列表，点了分类像没反应。
  - 卡片区是**一个网格集合铺**（不再按性别分块）：没有组标题、没有组间距，
    不分类时也不是三段，就是一整片卡片（顺序仍是 女 → 男 → 未标注，稳定不乱跳）。
  - 头像 / 身份 / 简介来自后端快照（发现任务每轮顺带补一次演员档案），所以打开面板
    即可见；刚安装、或想立刻补上头像时，点槽位里那个刷新按钮（`/actors/cards?enrich=1`，
    后端最多现抓 12 位）。没补到档案的演员显示人形占位图。
  - 卡片**照宿主演员卡（`PersonCard`）复刻**：2:3 卡面（45° 渐变底）+ 居中**圆形大头像**
    （100px，图片加载完加 1px 描边）+「演员」小字 + 粗体姓名 + 身份行（作品数 · 职业 ·
    性别 · 国籍，两行省略）；悬停抬升 4px，浮层里放本插件自己的两个钮 ——
    左「百科演员页」、右「关注 / 取消关注」。
  - **点卡片进「演员作品页」**（**整页**，见下方「演员作品页」一节）：卡片区整块让位，
    从面板顶部铺满；返回键回原来那一页。档案与作品由后端现查
    （`GET /actors/detail`，关注与否均可）。
  - 暂未取到作品（会自动重试）或百科未收录的演员，身份行会写明原因，卡片照常可点。
  - 一位演员都没关注时，演员页是引导空态（去「搜索」行搜人后点卡片上的「订阅」）。
- **作品标签页**：海报墙沿用宿主「探索」页版式 —— **海报卡片**（2:3，自适应列宽）+
  宿主 MediaCard 同款角标（左上「短剧」、右上评分）+ **悬停浮层**（年份 / 剧名 / 简介 +
  左搜索右订阅按钮排，hover 抬升 4px）。**点卡片进本插件自绘的作品详情页**（见下方
  「作品详情页」一节；卡片与详情页里都**没有**「跳系统详情页」的入口）。
  - 右上角角标：**有评分显示评分**（`8.3`），**没有评分显示首播日期**（`10-16`，悬停有说明）。
    这一手是必要的：按「发布日期」排序时首屏全是当天新剧，百科还没给它们打分
    （`vote = 0`），不补日期的话整屏卡片右上角都是空的。
  - 已入库的作品在**未悬停**时右上角显示绿色对勾（与探索页一致），悬停时才换评分 / 日期角标。
- **向下滚动自动加载下一页**（与探索页**同一套机制**，2026-10 复刻验证）：首屏 60 部，
  滚到底再取下一批，页尾显示「已到末尾 · 共 N 部」。
  - **虚拟滚动网格**（`src/ProgressiveCardGrid.vue`，宿主 `ProgressiveCardGrid` 同款复刻）：
    整份列表的高度由上下 spacer **立即**撑出（行高 = 列宽 × 1.5 估算 + ResizeObserver
    实测校正），**DOM 只挂载「视口 ± 4 行」的卡片**，渐进挂载每帧一批（与宿主同节奏）。
    拉了几十页也只会有几十张卡真的在 DOM 里 —— 这是探索页「滑到哪加载到哪」的真正答案。
  - 加载触发与探索页同语义：一次触发拉**一页**，哨兵离视口 600px 内才续拉
    （IntersectionObserver `rootMargin: 600px` + 加载完后按几何距离重判，等价于
    VInfiniteScroll `mode="intersect"` 在 items 变化后重算距离）；首屏不满一屏时
    天然连拉到「出现滚动条」为止 —— 虚拟网格保证第一页一进列就有全长滚动条，所以
    实际只拉 1 页上下。
  - ⚠️ 滚动发生的位置要找对：宿主在 `layout-content-height-fixed` 布局模式下把页面
    内容的第一层子元素钉成**自带纵向滚动的固定高容器**（`.page-content-container >
    :first-child { max-block-size: 100%; overflow-y: auto }`）—— 插件面板里**滚的不是
    window / body**。哨兵位置与滚动位置记录 / 恢复（进详情返回跳回原处）从网格往上
    找最近的可滚祖先（`scrollHost()`，WeakMap 缓存 + 节点切换时重探）；window 只是兜底。
  - **恢复进度有上限（最多补 8 页）**：sessionStorage 里存的是「离开时拉到第几页」，
    旧版判错容器时那里可能是全集 38 页 —— 照单全收就是「点开就全部加载」。超过上限的
    部分不补；存储键也从 `filters.v2` 升到 `filters.v3`（旧值一次性作废）。
    跳转不用等卡片铺出来 —— spacer 已把高度撑好，直接按像素跳。
  - 历史：更早的版本是「全量挂载 + `visibleCount` 渐进填充」，DOM 随页数无上限增长，
    与填充链互相追赶导致反复「一次拉完 + 页面卡死」，这轮随虚拟网格一并拆除。
- 作品维度筛选行**与宿主「探索」页同一套组件**：一行一个维度，
  左侧是维度名（`VLabel`：版权方 / 类型 / 年份 / 排序 / 媒体库，顺序按用户定的排版），
  右侧是 `VChipGroup` 里的一排 `VChip{filter, tile}` —— 选中项前面的 ✓ 就是 `filter`，
  主色高亮，**再点一次即取消**（没有「全部」按钮，与探索页一致）。
  - **版权方**（真机 60 项）、**类型**（真机 60 项）选项多，
    **默认只铺一行（12 项）+ 行尾「展开」按钮**，展开后铺全部并可「收起」；
    展开行是**换行排布**（column 模式），没有左右滑动箭头；每项都带作品数，按作品数从多到少排；
  - **排序**是「发布日期 / 热度 / 播放 / 评分」，排的全是作品自带的真实数值
    （**默认「发布日期」，新剧在前**；缺数据的作品排最后）；
  - **媒体库**行是「只看未入库」开关（作品卡右上角绿色对勾 = 已在库，判定与媒体详情页一致）；
  - 后端 `/works` 的 `actor` 筛选参数仍保留给脚本使用（面板不再用它筛选）。
- 筛选栏里**没有任何按钮**（探索页同款）：加演员走「搜索」行搜人后点卡片上的「订阅」，
  设置在宿主的插件管理里进。

### 与宿主「探索」页一比一的部分

版式与**交互**都按宿主探索页那一套复刻（数值直接取自宿主源码，不是「看着像」）：

| 位置 | 与探索页同款 | 本插件对应 |
| --- | --- | --- |
| 首屏加载 | `LoadingBanner`：4 个主色圆点依次上下跳（1.5s 循环），容器 20vh 高 | `src/LoadingBanner.vue` |
| 空态 | `NoDataFound`：超大错误码（数字 `0` 换成**旋转的胶卷盘**）+ 三片漂浮胶片帧 + 辉光呼吸 + 标题下划线 + 上浮入场 | `src/NoDataFound.vue` |
| 海报骨架 | `VSkeletonLoader`（宿主 Vuetify 组件全局注册，CSS 由宿主提供） | 卡片 `v-img` 的 `#placeholder` |
| 海报淡入 | 首次显示淡入；**同一张海报再出现时不做动画**（分页重建不闪） | `v-img` 的 `transition` + 已展示登记表 |
| 类型徽标 | 颜色按媒体类型走，**电视剧 = 靛蓝** `bg-indigo-500 border-indigo-600` | 作品卡左上「短剧」徽标 |
| 卡片悬停 | `app-hover-lift-card` 上浮 `0.25rem` + `ring-1` 描边 | 同一套宿主全局类 |
| 触摸端点击 | 无 hover 的设备：**第一次点只展开浮层，第二次点才进详情**；点到卡外收起 | 作品卡 `handleClick` |
| 作品区毛玻璃 | glass 主题下把所有**静止**卡片的圆角并集交给**一个**采样层（悬停中的卡片自己采样，动画结束再收编；海报盖住卡片后停采样） | `src/GlassMediaBackdrop.vue` |
| 空态 / 加载的组件边界 | 加载态只在「一张卡都还没铺出来」时出现；有数据后的翻页加载**不显示**加载条 | 同 |

三处**故意不一样**（数据面决定的，不是漏做）：

- **筛选行**：探索页的 chip 组是**一行横向滑动 + 左右箭头**；这里因为「版权方 / 类型」
  真机各有 60 项，一行横滑基本没法用，改成了**默认只铺一行（12 项）+ 行尾「展开」按钮**，
  展开后换行铺全部。chip 本身的用法（`filter` + `tile` + 主色高亮 + 再点取消）与探索页一致。
- **演员列表没有毛玻璃采样层** —— 宿主那边也只有**作品列表**有（`PersonCardListView`
  用的是普通 `PersonCard`），这里保持一致。
- **演员作品页的作品一次给全**（`GET /actors/detail` 一次返回全部），
  宿主那一页是分页接口滚动加载；省掉一层翻页交互，滚到底即结束。

> 毛玻璃那一条**只在宿主主题切到 `glass`** 时可见（且要 `prefers-reduced-transparency`
> 没开启、浏览器支持 `clip-path: path()` 与 `backdrop-filter`）；其它主题下这一层退化成
> 普通包裹元素，零副作用。

### 筛选与排序口径

| 维度 | 数据来源 | 说明 |
| --- | --- | --- |
| 类型 | 作品卡的题材标签 | 卡上是**摘要**（只印 1~3 个），详情页才是全量 ⇒ 这一栏按摘要标签筛 |
| 年份 | 作品首播年 | 卡片只给首播日期时取年份部分 |
| 演员 | 本插件的关注名单 | 面板上切到顶部标签条的**「已关注演员」**看卡片墙（点卡片进**演员作品页**看其全部作品）；一部剧多位演员参演时，命中任一即可 |
| 版权方 | 作品数据源 | **目前只有作品详情页才有**；数据源把这一项补进作品条目后，这一栏自动出现（没有数据时整栏隐藏，不拿空标签充数） |
| 排序 · 发布日期 | 作品的首播日期 | **默认排序**，降序（新剧在前）；没有日期的作品排最后 |
| 排序 · 热度 | 作品自带的热度 | 降序；没有该数据的作品排最后 |
| 排序 · 播放 | 作品自带的播放量 | 降序；没有该数据的作品排最后 |
| 排序 · 评分 | 作品自带的评分 | 降序；没有评分的作品排最后 |

> 站点的**演员页卡片只印**「热度 / 播放 / 首播 / 标签 / 评分 / 集数」这几项，
> 没有「收藏」这个数据（演员页、详情页、排行榜都没有）—— 所以排序里没有收藏。

筛选、排序、分页都在**后端**做（真机 95 位演员 = 2256 部），前端只负责取当前页。

## 卡片上的三个动作

| 动作 | 行为 |
| --- | --- |
| **搜索**（悬停浮层左下放大镜） | 跳宿主的资源搜索页 `#/resource?area=title&media_source=djbaike&media_id=…`，参数口径与宿主 MediaCard 的 `handleSearch` 一致；**配置页勾选了「资源搜索站点」时**额外带 `sites=<id,…>`，只在配置的站点里搜（不勾 = 走系统默认） |
| **订阅**（悬停浮层右下爱心，与系统同款） | 调宿主注入的 `nativeSubscribe`，弹出**系统自带的订阅对话框**（选季、质量、目录等一律由系统负责），建出来的就是系统订阅 |
| **点卡片** | 打开**整页的作品详情页**（`GET /works/detail`，全屏铺满面板）—— 见「作品详情页」一节 |

已订阅的作品，浮层里的爱心会变成红色实心（读宿主 `subscribe/` 列表里 `media_source` 为
`djbaike` 的条目；换源前用 `duanju` 建的历史订阅也一并认）；
海报上的角标只有「短剧」类型徽标与右上那一枚（**评分**，没评分时是**首播日期**）两枚，
与探索页 MediaCard 同款，右下来源角标用宿主自带的 MDI 图标（不引外链资源）。

> **`djbaike` 是唯一来源标识（2026-10-22 换源）**：它是短剧百科数据源
> `ShortDramaBaikeScraper` 对外声明的**规范标识**（老数据源 `ShortDramaNetSource` 的
> `duanju` 已随换源丢弃；换源前用 `duanju` 建的订阅仍在宿主里，照常生效），
> `media_id` 则是**复合形态 `<站点分类>:<数字>`**（`duanju:39980`、
> `manju:7696…`；分类前缀是身份的一部分，剥了就会把别的分类下同号的作品认错）。
> **只有一个数据源**：本插件不认任何其它短剧数据源的历史身份 —— 别家站点的号段与这里
> 完全无关。数据源给的 ID 唯一且固定是「分类 + 纯数字」，所以不做前缀黑名单那类猜测：
> 形态不符（URL / 乱码）一律不收，由发现流程按名字重新解析一次。

## 作品详情页（面板自绘 · 全屏整页）

**点卡片不再跳宿主的媒体详情页**，而是打开**本插件自绘的整页详情页**（`WorkDetail.vue`）——
它**不在面板里**：顶栏的标题行 / 搜索行 / 标签条 / 槽位整块让位，从面板顶部铺满，
左上角浮着一个**纯图标「返回」键**回到进来之前那一页并恢复滚动位置（宿主那一页靠顶栏与
浏览器返回，插件面板没有 ⇒ 做成不占排版的绝对定位浮层）。换标签、改筛选、或在搜索栏里
输个词也会自动退出（否则会卡在这一页上，点了像没反应）。

版式**照宿主「探索」页点进作品详情页的那一页一比一复刻**（对过它的模板与 scoped 样式，
尺寸直接搬），效果与系统那一页一致：

| 区块 | 与宿主同款的细节 |
| --- | --- |
| 顶栏大图 | 剧照首图（没有则海报）**两层绝对定位铺满整宽**（不受内容 1rem 内边距影响）、高 **24rem**；一层放图、一层放四向渐变（上/下/左/右）把边缘收到页面底色。内容块从**页面顶部**起叠在它上面 —— 宿主 `.media-page` 那对 `margin-block-start: -4rem` / `padding-block-start: 4rem` 是穿过它顶栏用的、净效果为 0 |
| 海报 | **8rem / 11rem（≥768px）/ 13rem（≥1280px）** 三档宽度 + 圆角（`--app-surface-radius`）+ 1px↔25px 双层阴影 |
| 标题行 | `h1` **≥1024px 就横排**（宿主 `flex-lg-row`）、字号 1.5rem → **2.25rem**（≥1280px），年份跟在标题后；「已入库」绿色胶囊与「新作品」「真人短剧」角标同款 |
| 属性行 | 「N 分钟 \| 题材」（与宿主一样，`\|` 只在两项都有时出现） |
| 操作按钮排 | 窄屏两列网格 → **≥640px 起变一行右对齐**（宿主 `.media-actions` 的三档规则原样搬）；按钮为「搜索资源 / 订阅 / 百科页」 |
| 信息面板 | 宿主 `.media-facts` 同款：首行 **10 星 `VRating`** 居中，其余行两端对齐 + 1px 分隔线（末尾一行去线）；`ID / 状态 / 上映日期 / 集数 / 单集时长 / 全集时长 / 原始语言 / 制作公司` 沿用宿主的中文文案，上映日期那行带宿主同款云朵图标。`ID` 是**百科 ID**；百科严格匹配到 TMDB 条目时（见下）紧跟一行 **`TMDB ID`** |
| 两栏自适应 | 宿主是「左简介 + 右信息面板」**并排**、行高由更高的那一侧决定；它的左栏有长简介 + 导演列表、填得满，而短剧简介只有一两行（实测 116~164 字）⇒ 并排时左栏下方会露一大片空白，正好夹在来源链接与演员阵容中间。所以改成按**内容高度**自动选：够高 ⇒ 照宿主并排；左栏比信息面板矮 **2rem 以上** ⇒ 单列（简介 → 来源 → 信息面板 → 演员阵容），信息面板同时拆成 `repeat(auto-fill, minmax(17rem, 1fr))` 多列网格，免得整宽一行被拉到两端相去很远（网格线只画每格的**上边** + 容器的**下边**：同行格子共线、最后一行没填满也不缺角、也不会与容器边框叠成双线） |
| 来源 | 宿主同款 link chip（gray-600 底 + gray-500 描边 + `mdi-link`）：**短剧百科**；有 TMDB 身份时多一个 **TheMovieDb** chip（地址拼法与宿主 `getTheMovieDbLink()` 逐字一致：`https://www.themoviedb.org/tv/{id}`）；有豆瓣身份时多一个**豆瓣** chip（`https://movie.douban.com/subject/{douban_id}/` —— 短剧在豆瓣的覆盖率比 TMDB 高，通常这一个才出现） |
| 演员阵容 | 宿主的演出阵容是**横滑人物卡**（`PersonCardSlideView` → `VirtualSlideView` → `PersonCard`），不是网格 —— 标题竖条 + 「演员阵容」+ **9rem 的 2:3 卡**（圆形头像 **100px**（图加载完才加 1px 描边）+ 固定「演员」+ 姓名粗体一行省略 + 角色两行省略 + 45° 渐变底）、悬停上移 4px、左右翻页圆钮（40px 圆形玻璃钮，悬停或滚动中淡入，触摸端不显示）；**credits 未回来时先摆 10 张 2:3 空卡骨架**。卡片上**没有悬停浮层、没有动作按钮** —— 与宿主那一张完全一致 |
| 首屏加载 | 宿主 `LoadingBanner`（4 个主色圆点 1.5s 依次跳动，`mt-12`）—— **时序与宿主逐条对齐**：宿主是 `v-if="!isRefreshed"`，请求完之前**整页只有圆点**、不摆内容也不摆骨架（本页 `loaded` ≡ 宿主的 `isRefreshed`）。请求在 setup 期就发出 ⇒ 首帧即圆点，不会先闪一版上一部剧的内容；**换一部剧**（组件被复用时）三个状态清零重拉，与宿主「路由跳转 = 新实例」同构 |
| 取数失败 | 宿主 `NoDataFound`（**500** + 超大数字里的 `0` 换成旋转胶卷盘 + 三片漂移胶片帧 + 标题下渐变小横线，「重试」按钮放它的 `#button` 槽位）—— 对应宿主的 `detailLoadFailed`（本页 `failed`）：文案照宿主 i18n 原话「出错啦！」/「无法获取到媒体信息，请检查网络连接。」，请求异常只进控制台（宿主也一样），「重试」是面板里没有浏览器后退那条退路才保留的增量 |
| 主题特化 | 玻璃 / 透明主题下**隐藏四向渐变层**、大图改**四边遮罩渐隐**并降到 **88% / 78%** 不透明（宿主 `.media-detail-glass` / `-transparent` 的 `.vue-media-back-*` 规则原样搬）；玻璃主题下来源 chip 一并玻璃化（`--glass-*` 那套变量） |

> 宿主那些 `.media-*` / `.vue-media-back*` 类名是**它自己 scoped 的**（选择器带 `data-v`
> 属性），联邦模块的元素匹配不上 ⇒ 版式只能复刻、不能复用；样式一律走自有 `sdas-*` 类名
> （联邦 CSS 门禁会丢掉任何含 `.v-` 的选择器）。宿主的**全局**工具类
> （`app-hover-lift-card` / `ring-1` / `text-medium-emphasis`，定义在 `src/styles/common.scss`）
> 是全局的，联邦元素能吃到，照用。

> **为什么要自绘**：宿主详情页的**右侧信息面板 / 演员阵容 / 推荐 / 分季全部以 `tmdb_id`
> 为前提**（`MoviePilot-Frontend` 的 `MediaDetailView.vue` 里这几块整段包在 `v-if="tmdb_id"`
> 里），而短剧大多不在 TMDB 上 ⇒ 那一页右侧是**整块空白**，演员阵容也不渲染。
> 播放量 / 热度 / 真人·AI 角标这些站点字段，宿主 `MediaInfo` 模型里更没有。
> 本页把这些一起给全，并且**不引入任何跳系统的入口**。

> **TMDB 身份照实透出**（2026-10-16 用户指定）：短剧百科数据源会按「片名 + 首播年」严格匹配
> TMDB 条目，**匹配上就把 `tmdb_id` 写进 `MediaInfo`**（如「夏星望野」= 百科 `30409` /
> TMDB `326627`）。本插件的 `/works/detail` 把它**原样透出**，详情页因此多两处：
> 信息面板一行 `TMDB ID`、来源区一个 TheMovieDb chip —— 与系统那一页同样能给出 TMDB 入口。
> **但 TMDB 自己的演职员 / 推荐 / 相似 / 分季不搬过来**：那些是 TMDB 的条目（TMDB 人物 id ≠
> 百科演员 id），点开回不到本插件的数据面（本页所有卡片都指向百科身份），搬过来只会多出
> 一批"点了没反应"的卡片。演职员在本页由**百科演员阵容**承担（还带饰演角色，信息更全）。

详情页的数据面两拨（`GET /works/detail`，`media_id` 必填、历史前缀照收）：

| 来源 | 提供的内容 |
| --- | --- |
| 短剧百科 `recognize_media`（宿主模块合同，返回标准 `MediaInfo`） | 简介 / 题材（**全量**，不是卡上那 1~3 个摘要）/ 出品方 / 评分 / 状态 / 首播日期 / 单集时长 / 集数（+ 折算出的全集时长）/ 语言 / 海报 / 剧照首图 / **演员阵容**（姓名 · 饰演角色 · 主演·配角 · 头像）/ **TMDB 身份**（`tmdb_id` + 拼好的条目地址，匹配上才有） |
| 本地快照的**墙上那一行**（按归一后的百科 ID 精确命中） | **热度 / 播放量 / 真人·AI 标签 / 首次发现时间 / 是否新作品 / 在库状态** —— 这些字段 `MediaInfo` 里压根没有 |

- 卡上的值只用来**补空**（站点详情页没解析出某项时才拿卡上的兜底），详情页解析出来的更权威；
- **全集时长是折算值**：站点只印全集总时长，`MediaInfo` 只保留单集时长 ⇒ 用「单集 × 集数」还原；
- `is_new` / `in_library` 与作品墙**同一口径**现算（过期的「新」自动消失；在库查询失败给「未知」
  而不是「不在库」），所以同一部剧从**作品墙 / 搜索结果 / 演员作品页**三个入口点开，
  详情页显示的信息一致；
- 演员阵容那一张卡**点一下钻进这位演员** —— 与宿主同一套行为（宿主点人物卡进它的人物详情页，
  本插件打开**演员作品页**`ActorDetail.vue`）；在那个页面里点左上「返回」会**退回到作品详情页**
  （位置也照原样还原），与宿主的浏览器历史同构。站点没给演员 id 时退化成打开百科演员页；
- **这一块的「更多 ›」没有做**：宿主 `VirtualSlideView` 的标题行右侧有个「更多」链接
  （`linkurl`），指向宿主的 credits 全页；本插件没有对应页面，硬放一个点了没反应的按钮更糟，
  所以按宿主「没有 linkurl 时」的形态留空；
- 百科里没有这部剧时给 `success=true` + `found=false` 的空壳（前端出空态），**不算接口失败**。

### 豆瓣短评 / 影评（2026-10-18 新增）

作品详情页在**演员阵容之后**还有一块「豆瓣短评 / 影评」双标签区 —— 系统详情页那两块就是靠
`douban_id` 从宿主 `/api/v1/douban/*` 取的，这里用**同一批接口、同一份数据**：

- **数据面**：数据源 `recognize_media` 严格匹配到豆瓣条目时把 `douban_id` 写进 `MediaInfo`，
  `/works/detail` 原样透出（`douban_id` + 拼好的 `douban_url`）。**没有豆瓣身份
  （大多数短剧没有）就整块不渲染**，与系统侧同判；
- **接口**：短评走宿主 `GET /api/v1/douban/interests/{douban_id}/{type}`、影评走
  `GET /api/v1/douban/reviews/{douban_id}/{type}`。`type` 按**作品类型名**映射
  （`电影` → `movie`，其余一律 `tv`；宿主这两个接口按 movie/tv 分表，同一个 id 两边结果不同，
  实测短剧只有走 `tv` 才有短评与影评），分页参数与系统一致（`start` + `count`）；
- **版式**照系统那一页（`MediaCommentView.vue`）复刻：两个自绘标签（带条数角标，
  点击用容器委托）、列表项为 头像 + 作者 + 内容 + 时间/有用数，影评标题可点开豆瓣原文；
- **失败静默**：接口失败（豆瓣限流是常事）只静默返回空页，不弹错、不占位；
- **顺序口径（2026-10-19 用户定）**：**演职员排在豆瓣短评 / 影评之前** —— 先看人，再看评价。

### 改编自 · 原著详情页（2026-10-18 新增）

站点在**剧集记录**里带 `adapted_from`（原著的书名 / 作者 / 字数 / 题材 / 简介 / 封面 /
原著页地址 / **全部改编作品**）。作品详情页的数据第二块（数据源原始记录
`/catalog/detail`，见上）把它投影成 `adapted` 字段透出，于是：

- 作品详情页多一块**「改编自」**区（书名 + 作者 + 封面；不是改编作品时整块不渲染）；
- 点「改编自」打开**整页的原著详情页**（`AdaptedDetail.vue`，**叠在作品详情页之上**，
  左上「返回」退回作品详情页 —— 不是回到列表）：封面 + 标题 + 作者/字数/题材副信息 +
  简介 + **「改编作品」网格**，网格里每一部都可点开进那部剧的详情页（再返回时回原著页）；
- **进原著页零额外请求**：剧集记录里的 `adapted_from.works[]` 已带全部改编作品，
  整份 `AdaptedInfo` 由父组件直接传入；
- 唯一的补拉：老记录的 `adapted.works[]` 可能为空（改编作品列表要拿**原著自己**的记录才有），
  此时按 `media_id`（`xiaoshuo:<id>` 或剧 id）向数据源
  `plugin/ShortDramaBaikeScraper/novel` 补一次取全（详情缓存命中，零额外抓取）；
  取不到就按已有内容显示，不出错。

## 演员作品页（面板自绘 · 全屏整页）

**点演员卡不再在卡片区里展开**，而是打开**本插件自绘的整页演员作品页**（`ActorDetail.vue`）——
同样不在面板里（顶栏 / 搜索行 / 标签条 / 槽位整块让位，从顶部铺满，左上「返回」回原页）。

版式**照宿主「探索」页点演员进的那一页（`PersonDetailView.vue`）逐条复刻**：

| 区块 | 与宿主同款的细节 |
| --- | --- |
| 头部 | **圆形大头像 200px**（图片加载完加 `ring-1 ring-gray-700`）；窄屏竖排居中 → **≥768px 横排**（宿主 `flex-md-row` 断点原样搬） |
| 姓名 | `h1` 1.875rem → **2.25rem**（≥1280px），窄屏居中、≥768px 靠左 |
| 副信息行 | 宿主的「生日 \| 出生地」+ 别名两行，我们换成本插件数据源真有的：**「职业 \| 国籍」**+「参演 N 部短剧 · 已入库 M 部」（.net 源没有职业 / 国籍时该行自动隐藏，只留作品数那一行） |
| 简介 | `pt-2 text-sm lg:text-base` + `overflow-wrap: break-word`（宿主同款） |
| 参演作品 | 宿主全局类 `slider-header` / `slider-title`（那两行是全局样式，联邦元素能直接用）+ `mdi-arrow-right-circle-outline`；下面是**作品卡网格**（与作品墙同一张卡、同一套列宽下限 144 / 间距 16） |
| 本插件动作 | 简介下面一行 tonal 按钮：「关注该演员 / 取消关注」+「百科演员页」（宿主那一页没有这一块，因为它的关注入口在别处） |
| 首屏加载 / 失败 | 与作品详情页同一套时序（宿主 `PersonDetailView` 的 `isRefreshed`）：加载中整页只有 `LoadingBanner` 圆点，**不用卡片兜底顶着**；失败换 `NoDataFound`（500 + 同两句文案 +「重试」）；百科没这位演员 ⇒ 404 空态。**换一位演员**同样清零重拉 |

> ⚠️ **字段对不上是正常的**：宿主副信息行放的「生日 \| 出生地 / 别名」是它那几个源
> （TMDB / 豆瓣 / Bangumi / AniList）才有的东西，**短剧百科没有**；百科有而宿主模型没有的是
> 「职业 / 国籍 / 作品数」。所以这里照的是**版式**（位置 / 字号 / 断点），数据面用自己能有的。

演员作品页的数据面（`GET /actors/detail`，`actor_id` 或 `name` 至少给一个）：

| 来源 | 提供的内容 |
| --- | --- |
| 短剧百科 `actor_profile`（`enrich=false`） | 姓名 / 头像 / 简介 / **职业** / 国籍 / 性别 / 百科演员页地址 |
| 短剧百科 `actor_works` | 全部作品（每条都已补成作品页记录，投影与 `/actors/works` **同一段代码**） |
| 本地快照（现查拿不到时**补空**）+ 关注列表 + 在库探针 | 头像 / 简介兜底、是否已关注、`in_library_count` / `library_known`（三态口径：查不了的不算数） |

- 档案那一路失败**不影响作品**（降级成「只有作品」，只记日志）；作品那一路失败才是 503；
- 百科两路都空 = 「没这位演员」⇒ `success=true` + `found=false` 空壳。

## 添加演员

界面上只有一条路：**「搜索」行搜人 → 卡片点「订阅」**。插件先到短剧百科里查：

- **完全同名**的候选只有一位 → 直接采纳；
- 有多位候选 / 没有完全同名 → 把候选都列出来让你点一位确认（**绝不自动错配**成另一个演员）；
- 百科没收录 → 显示「没找到」（这是稳定结果，不是故障）。

解析出的百科演员 ID 会写进快照，之后每轮直接按 ID 取作品页，不再走站外索引。

也可以在**宿主插件管理的设置页**里用文本框**批量粘贴**（一行一位或用逗号分隔）。

## 搜索演员 / 作品

面板顶部那条**搜索行**（两个标签页共用）**演员与作品都查**（短剧百科同一站，两条检索链路并行，防抖 0.4 秒）：
有词时搜索结果独占卡片区 —— 上半块是演员、下半块是作品；清空后回到当前标签页那一页。

演员结果用与作品墙**同一套卡片**渲染 —— 「海报」位放演员头像，悬停浮层显示
作品数 / 身份 / 姓名 / 简介，卡上两个动作：

| 动作 | 行为 |
| --- | --- |
| **百科页** | 新标签打开百科的演员页 |
| **订阅（人形 + 号）** | 把这位演员**加进本插件的演员表**（不是剧集订阅），加了之后演员页与作品墙立即带上他；已在列表里的显示绿色对勾 |

头像与作品数来自百科插件的演员档案（`/actor` 接口，卡片先出、头像渐进补上，
补不到就显示人形占位图）。**搜索是查站外索引，慢的时候 40 秒级**，前端已放宽超时；
百科没召回时显示「没找到」空态 —— 换个名字再试即可（百科只收录站上有的演员）。

## 刷新节奏

| 节奏 | 默认 | 说明 |
| --- | --- | --- |
| 作品发现 | 12 小时 | 逐演员向数据源取一轮作品，更新「首次发现」映射与新作品通知 |
| 失败重试 | 20 分钟 | 解析失败是可自愈的临时故障，按分钟级重试 |
| 作品/档案读取 | 5 / 60 分钟 | 作品读**快照**（纯内存）；快照里还没作品的老记录才走进程内缓存 → 数据源。档案只走进程内缓存（不落盘） |

**作品随快照落盘**（2026-10-19 起，`schema=5`）：每位演员的记录里带一份 `works[]`，
只存**身份 + 作品墙要用的字段**（`media_id` / `title` / `year` / 海报 / 地址 / 评分 /
集数 / 题材 / 热度 / 播放 / 出品方 / 平台 / 角标 / 首播日期）—— 作品墙、详情页兜底、
自动订阅都读它，不再每次逐演员打数据源；长篇简介 / 演职员这类内容字段仍**运行时向数据源要**。
v4 及更早的记录（作品不落盘的瘦身形态）在读入时自动迁移出 `first_seen` 映射，并保留原
`schema` ⇒ 下一轮由版本门触发一次重抓，把作品补进快照（补齐前作品墙走数据源兜底）。

首轮解析可能拉长到几十分钟（每位演员一次站外索引检索），因此**每解析完一位就落一次盘** ——
宿主随时可能重载插件，整轮结束才写盘会把进度全丢。

## 「新作品」的口径

作品的**首播 / 上映日期**（`release_date`，作品卡上印的就是它）距今在 **7 天**内 ⇒ 标「新」。

- 与「什么时候第一次发现它」无关：换源 / 刚关注 / 一次导入十几位演员都会让整片作品同时
  「首次出现」，拿 `first_seen` 当新会一次刷出上千部（`first_seen` 只作「首次发现」展示）；
- 缺日期、日期在未来（预约剧）一律**不算新** —— 宁少不错；
- 标记**不落盘**，每次查询现算，所以过了窗口的「新」会自己消失；
- 同一口径贯穿三处：作品墙标记、`/status` 的 `new_works` 计数、自动订阅的「只订新作品」。

## 接口（`auth: "bear"`，面板与脚本可共用）

**响应格式（V3 合同）**：所有普通 JSON 端点都返回宿主统一信封
`{"success": bool, "message": str, "data": {...}}` —— 顶层只有这三个键，**业务对象一律在
`data` 里**（每个端点的 `data` 结构都在路由上声明了 `response_model`，可在宿主 `/docs`
的 OpenAPI 里查）。参数 / 资源 / 状态类错误改用 HTTP 状态码表达：**400** 参数或前置条件
不满足、**404** 资源不存在、**409** 重复添加或刷新冲突、**503** 上游（短剧百科）不可用；
`200 + success=false` 只留给「调用已完成但业务被拒」。查询正常完成但没有结果时仍是
`success=true` + 空结果（例如 `/actors/add` 需要用户在候选里挑人时返回
`data.need_pick=true` + `data.candidates`）。

| 方法 | 路径 | 说明（`data` 内容） |
| --- | --- | --- |
| GET | `/status` | 演员数 / 作品数 / 新作品数 / 最近刷新 + 每位演员的状态（只出统计，不查媒体库）+ 自动订阅口径（开关 / 累计成功部数 / 最近 5 条记录） |
| GET | `/works` | 作品墙，一页一条记录。参数：`actor` / `genre` / `year` / `studio` / `sort`（`heat`\|`play`\|`rating`\|`date`）/ `keyword` / `only_not_in_library` / `page` / `page_size`。`data` 带 `total` / `has_more` / `works` / `actor_filters` / `facets`（类型·年份·版权方及各自作品数）/ `summary` |
| GET | `/actors` | 演员列表（含解析状态、百科 ID、作品数） |
| GET | `/actors/cards` | **已关注演员的卡片数据**（面板卡片墙用）：字段与 `/actors/search` 候选同构（头像 / 简介 / 身份 / 作品数 / 是否已关注）+ `state`。档案优先读快照缓存；`enrich=1` 时现抓还没档案的演员（最多 12 位）并写回快照 |
| GET | `/people` | **人物目录的一页**（面板「发现演员」页用）。参数 `kind`（`yanyuan` 演员 / `daoyan` 导演 / `bianju` 编剧，非法值回落演员）+ `page`（从 1 起）。数据源侧对应站点 `/<kind>/list.html?page=N`（24 条/页），本插件只转发 + 标 `subscribed`，**不入 ID 库**。数据源还没提供 `list_people` 时返回空列表 + `message` 说明（`success=true`，不当接口失败） |
| POST | `/actors/search` | 在百科里查演员。请求体 `{name, enrich}`；`enrich` 为真时给前 12 位候选补档案（头像 / 作品数 / 简介 / 性别 / 国籍，补不到就只有名字） |
| POST | `/works/search` | 在百科里按**片名**查作品（与宿主搜索框同一条链路）。请求体 `{name}`。站内搜索会把小说频道（`xiaoshuo:…`）条目混进来，这里**只回剧集** |
| GET | `/works/detail` | **一部作品的详情**（面板自绘详情页的数据源，不走宿主详情页）。参数 `media_id`（必填，**复合 ID `duanju:39980`**，历史 `org:` / `duanjubaike:` 前缀会被剥掉）`title` / `year`（兜底文案）。`data` = 百科 `MediaInfo` 投影（简介 / 题材 / 出品方 / 评分 / 首播 / 单集·全集时长 / 集数 / 语言 / 海报 / 剧照 / 演员表含角色与是否已关注 / **TMDB 身份** `tmdb_id` + `tmdb_url` / **百科地址** `url` —— 数据源不写 `homepage` 时按 `/{分类}/info-{id}.html` 拼）+ 墙上快照侧字段（`heat` / `play_count` / `kind` / `first_seen` / `is_new` / `in_library`）。百科没这部剧 → `found=false` 空壳（`success=true`）；缺 `media_id` → 400；百科不可用 / 投影失败 → 503 |
| GET | `/actors/detail` | **一位演员的详情**（面板自绘演员作品页的数据源）。参数 `actor_id` 或 `name`（至少给一个）。`data` = 百科档案（姓名 / 头像 / 职业 / 性别 / 国籍 / 生日 / 身高体重 / 星座 / 院校 / 爱好 / 粉丝获赞 / 代表作，来自数据源 `actor_profile`；职业缺了按「分类 + 性别」补「女演员 / 导演 / 编剧」）+ `actor_works` 全部作品（投影与 `/actors/works` 同源）+ `subscribed`（是否已关注）+ `in_library_count` / `library_known`（在库三态口径）。档案现查失败会用本地快照兜底、且**不影响作品**；百科两路都空 → `found=false` 空壳（`success=true`）；缺标识 → 400；取作品失败 → 503 |
| POST | `/actors/add` | 添加演员（`actor_id` 缺省时按同名精确匹配；需要用户挑人时 `data.need_pick=true` + 候选） |
| POST | `/actors/remove` | 移除演员（连同快照） |
| GET | `/actors/works` | 某位演员的全部作品（百科实时，关注与否均可）。参数 `actor_id` 或 `name` |
| POST | `/refresh` | 立即刷新全部演员 |
| GET / PUT | `/config` | 读写配置 |

## 自动订阅（可选，默认关）

打开后，**发现到的作品直接交给宿主订阅系统**（`app.chain.subscribe.SubscribeChain`，
与作品墙点「订阅」同一条链路），搜索 / 下载 / 整理全部由宿主接手，本插件不碰下载。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `auto_subscribe` | 关 | 总开关。订阅会触发下载，必须手动打开 |
| `auto_subscribe_scope` | `new` | `new` 只订「最近 7 天内上映」的作品（与「新作品」同口径）；`all` 连历史作品一起补订 |
| `auto_subscribe_max_per_run` | 5 | 单轮最多提交几部（1~50）。没轮到的**不记台账**，下一轮接着来 |
| `auto_subscribe_skip_library` | 开 | 已在媒体库的作品跳过（只认明确的「在库」，查询失败按未知照常订阅） |

**闸门顺序**：开关 → 台账已处理过（成功/跳过/失败都算）→ 范围（`new` 看首次发现时间）→
在库跳过 → 单轮预算。台账落在插件数据 `auto_subscribed`（最多留 500 条），
所以同一部剧不会被反复提交；「已在媒体库，跳过」也记进去，避免每轮重查。

**季集必须随订阅一起给**（与手动订阅同一口径）：`season=1` / `start_episode=1` /
`total_episode=作品卡集数`。不给总集数时宿主会重新识别一次媒体，而插件来源的识别结果
没有 `seasons` ⇒ 必然失败「媒体信息中没有季集信息」（宿主 `subscribe/create.py`）。
下载器沿用 `subscribe_downloader`。

日志与状态：每轮末尾汇总一条 `作品发现完成（…）：… ，自动订阅 N 部`；`/status` 里
`auto_subscribe`（开关）、`auto_subscribed`（累计成功部数）、`auto_subscribe_recent`
（最近 5 条，含失败原因）。

## 依赖

- **短剧数据源插件 `ShortDramaBaikeScraper`**（duanjubaike.net）必须已安装并启用 —— 作品全部来自它
  （2026-10-22 换源，老 `ShortDramaNetSource` 已丢弃；宿主媒体来源标识同步从 `duanju` 换成 `djbaike`）。
  取数**按插件 id 精确绑定**：`PluginManager().get_plugin_modules("ShortDramaBaikeScraper")`
  拿到该插件登记的方法表，再调 `search_actors` / `actor_works` / `recognize_media` /
  `search_medias` / `list_people`（若它登记了 `actor_profile` 则自动用上）。
  > **为什么不用 `self.chain.run_module`**：宿主模块分发器会把**返回 list** 的模块结果
  > **跨插件合并**（`runtime/extensions/module/dispatcher.py`），两个短剧数据源同时启用时
  > 演员检索结果会混在一起；按插件 id 取方法表才拿得到「只有这一家」的数据。
- 没装 / 停用时，演员会显示为「等待自动重试」，作品墙为空，不影响其它功能。

## 已知边界

- 作品卡上的**题材标签是摘要**（1~3 个）、**没有版权方**：卡上这两项不全会影响**筛选**选项
  （版权方这一栏等数据源把它带进作品条目后自动可用；现在没有数据时整栏隐藏，不拿空标签充数）。
  自绘详情页里的题材 / 出品方取自百科详情，是**全量**。
- 详情页**没有**「剧集列表 / 分季 / 推荐 / 相似 / 图集」—— 短剧本身不分季，站点也不提供这几项；
  即使这部作品在 TMDB 上有身份（本页会给出「TMDB ID」行与 TheMovieDb chip），那几块内容也不搬
  过来：它们是 TMDB 自己的条目（TMDB 人物 id ≠ 百科演员 id），点开回不到本插件的数据面。
  演职员的角色由**百科演员阵容**承担（带饰演角色，信息比 TMDB 那一栏更全）。
- 站点**没有「收藏」数据**，所以排序里没有收藏（现有四种：发布日期 / 热度 / 播放 / 评分）。
- 百科未收录的演员会稳定显示 `empty`（不是故障，不会反复重试）。
- **片名序号不做合并**：「云渺3：镇魔世家」与「云渺4：绝嗣佛子」是两部独立的剧，序号是唯一的
  区分键（只有「第 N 季/部」「SxxExx」「共 N 集」这类标记会在归一化时剔除）。
- 作品的媒体身份是**百科自己的 ID**：`media_source = djbaike` + `media_id` = **复合形态**
  `<站点分类>:<数字>`（形如 `duanju:39980` / `manju:7696…`）。**分类前缀不能剥** —— 站点各分类
  各排各的号，剥成裸数字会把 `manju` 的作品当成 `duanju` 的同号去查。**数据源给的 ID 唯一**，
  不需要按前缀去猜来源：形态不是「分类 + 纯数字」的（别家站点的号、URL、乱码）一律不收，
  缓存里遇到会重新按名字解析。
  宿主建订阅时若配置 `RECOGNIZE_SOURCE=themoviedb`，日志会留一条「未能转换为 TMDB 身份，
  订阅沿用原身份」—— 这是正常的，订阅照样生效。
- **「发现演员」页依赖数据源的 `list_people` 模块方法**（翻站点 `/yanyuan|daoyan|bianju/list.html`）。
  它对外的形状：`list_people(kind="yanyuan", page=1) -> {kind, page, has_more, people:[{name,
  media_id, url, poster, gender, job_title, works_count}]}`。数据源没登记时这一页显示
  「还没有提供人物目录」，其余功能不受影响；对面一旦登记，同一个面板自动就有数据（本插件不用再改）。
- **演员档案（简介 / 性别 / 国籍 / 职业）**：数据源登记了 `actor_profile` 就用它；没有时退回
  `search_actors` 的 `poster`（只有头像），缺的项留空、不用别的字段硬凑。
- 作品字段版本升级（例如作品条目新增筛选字段）后，旧快照会在下一轮刷新时自动重抓一次；
  重抓按剧名继承原有的「首次出现时间」，不会把整墙作品误判成新作品。
- 演员作品页会**一次性把这位演员的全部作品铺出来**（长尾演员可能上百部）—— 该页的数据面是
  一次请求拿全的，所以没有分页；作品墙本身照旧走滚动分页。
- 演员作品页的副信息行**不是**宿主的「生日 | 出生地」：短剧百科没有生日 / 出生地 / 别名，
  改成本插件数据源真有的「职业 | 国籍」（位置与字号照样照搬宿主那一行）。
